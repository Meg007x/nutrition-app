# Code Review & Roadmap — Nutrition App

## สรุปภาพรวม

โปรเจกต์มี 2 packages คือ `my-app/` (Expo + React Native) และ `nutrition-backend/` (Express 5 + Mongoose + Gemini AI) ไม่มี test suite, CI/CD, หรือ linter ที่รันอัตโนมัติ

---

## Part 1: Code Audit — จุดที่พบปัญหา

### 1.1 BUG ร้ายแรง (High)

| # | ไฟล์ | ปัญหา | รายละเอียด |
|---|-------|--------|-----------|
| **B1** | `dashboard.tsx:100-103` / `water-log.tsx:27` | **API Base URL ขัดแย้งกัน** | `services/api.ts` ใช้ `http://localhost:3000/api`, `constants/config.ts` ใช้ `http://10.168.100.38:3000`, `water-log.tsx` hardcode `http://localhost:3000`, `step6-2.tsx` hardcode `http://localhost:3000/api/ingredients`, `step7.tsx` hardcode `http://localhost:3000/api/disliked-foods` — ถ้ารันบนมือถือจริงจะเชื่อมไม่ได้ |
| **B2** | `dashboardController.js:80-96` | **Double-counting nutrients** | ถ้า MealLog มีทั้ง `totals` และ `items` จะบวก `kcal` สองรอบ ( totals + sum of items ) ทำให้ตัวเลขสารอาหารเกินจริง |
| **B3** | `dashboardController.js:108-116` | **nextMeal logic ผิด** | เลือก `mealSchedules[0]` ตลอดเวลา ไม่ได้เทียบกับเวลาปัจจุบัน — มื้อเช้าเลยไปแล้วก็ยังแสดงเป็น nextMeal |
| **B4** | `authController.js:97-110` | **Mapping ระดับกิจกรรมผิด** | Frontend step5 ส่งค่า `"light"` แต่ backend normalize เป็น `"ปานกลาง"` ซึ่งควรเป็น `"น้อย"` ทำให้ TDEE คำนวณผิด |
| **B5** | `register-context.tsx` + `_layout.tsx` | **RegisterContext ครอบทุกหน้า** | `RegisterProvider` อยู่ใน RootLayout ทำให้ทุกหน้า (รวม login, dashboard) โหลด RegisterContext ซึ่งไม่จำเป็น และ form data ยังค้างอยู่ใน memory หลังสมัครเสร็จแล้ว |

## Part 2: UX/UI & Logic Improvements

### 2.1 Registration Flow

| # | จุดที่ควรปรับ | รายละเอียด |
|---|-------------|-----------|
| **U1** | ไม่มี Back-to-Login | หลัง step1 กด back จะกลับ step ก่อนหน้าไม่ได้ (ใช้ `router.replace`) — ถ้า user อยากยกเลิก registration กลางคัน จะกลับ login ไม่ได้ |
| **U2** | ไม่มี "ข้าม" ใน step ที่ไม่บังคับ | step6 (allergies), step7 (disliked), step8 (cuisines) ไม่บังคับ แต่ไม่มีปุ่มข้าม — user ต้องกด "ไม่มี" หรือเลือกอย่างน้อย 1 รายการ |
| **U3** | Progress bar ไม่ตรง | บาง step กำหนด width hardcode (50%, 60%, 75%...) ไม่ได้คำนวณจาก step ปัจจุบันจริง |
| **U4** | step5 หายไป | step5 แสดง 4 ระดับกิจกรรม แต่ "sedentary" (นั่งทำงาน) หายไป — ตรงกับ mapping ใน backend ที่ sedentary = "น้อย" แต่ frontend ไม่มีตัวเลือกนี้ |
| **U5** | ไม่มี confirmation dialog | ก่อน submit registration ควรแสดงสรุปก่อน 1 หน้า หรือ confirm dialog |

### 2.2 Dashboard

| # | จุดที่ควรปรับ |
|---|-------------|
| **U6** | ไม่มี Pull-to-Refresh — user ต้อง force close app |
| **U7** | Water section ใน dashboard ไม่มีปุ่ม "+ ดื่มน้ำ" shortcut — ต้องกดเข้า water-log screen ทีหลัง |
| **U8** | แสดง macro bars 3 ตัว (protein/carb/fat) แต่ progress bar ไม่ overflow ถ้าเกิน 100% — visual bug |
| **U9** | ไม่มี empty state สำหรับ "มื้อต่อไป" ถ้า user ยังไม่ได้ตั้ง meal schedule |

### 2.3 ฟีเจอร์ที่ควรเพิ่ม/ปรับปรุง

| # | จุดที่ควรปรับ |
|---|-------------|
| **U10** | Plan tab (plan.tsx) ยังเป็น placeholder ว่าง — ควรมี meal plan หรือ weekly view |
| **U11** | Scan tab redirect ไป food-scan ตรงๆ — ไม่ได้เป็นหน้า scan เอง ทำให้ UX สับสน |
| **U12** | ไม่มี loading skeleton/shimmer ตอน load data — หน้า dashboard แสดง spinner ธรรมดา |
| **U13** | ไม่มี error boundary ทั่วทั้ง app — ถ้า component crash จะ black screen |
